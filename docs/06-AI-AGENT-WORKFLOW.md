# AI 编程助手协作规范

## 1. 角色

AI 编程助手是按任务执行的工程协作者，不是项目架构的自主决策者。GDD、架构和数据契约为规范源。遇到规范缺口先列出问题与建议，不得悄悄扩大范围。

## 2. 每个任务开始前

1. 阅读 README、ARCHITECTURE、对应系统规格和验收文件。
2. 检查当前分支、工作区、现有实现和依赖版本。
3. 明确本任务目标、不会做的内容、改动文件范围。
4. 查证 Forge 1.20.1 API，不得直接复制新版本/NeoForge 示例。
5. 先给出不超过 10 条的实施计划，再编码。

## 3. 执行原则

- 一次只完成一个可验证任务（例如 M0-003），不要一次实现整个 M0。
- 优先使用纯 Java 领域逻辑，Minecraft 交互通过 adapter。
- 所有数据修改走 Service/Repository。
- 不在 client-only 类中引用服务端类，反之亦然。
- 不直接操作其他系统的内部 Map。
- 不无故引入新依赖。
- 不为“看起来完成”而使用硬编码假数据。
- 不吞异常；输出对象 ID、操作、原因和恢复建议。
- 所有异步计算只处理不可变快照；世界操作回主线程。
- 修改字段/格式时同步 schema 和 migration。

## 4. 每个任务必须交付

- 代码变更。
- 新增/修改的测试。
- 构建与测试命令结果。
- 变更文件清单。
- 已知限制和未完成项。
- 文档更新。
- 如果未能运行 Minecraft 客户端或专用服务器，必须明确说明，不能声称已验证。

## 5. Definition of Done

- `./gradlew build` 成功。
- 相关单元测试通过。
- 有条件时客户端和 dedicated server 都启动成功。
- 保存/重载测试通过。
- 无新增未说明依赖。
- 无违反架构原则的跨层引用。
- 不存在 TODO 伪装成功的关键路径。
- 日志与错误处理可诊断。
- 任务验收标准逐条标注 PASS/FAIL/NOT RUN。

## 6. 禁止行为

- 不把远程 AI 基地设置为强制加载区块。
- 不用真实 NPC 数量代表逻辑人口。
- 不让 AI 获得未生产、未交易、未掠夺的资源。
- 不允许 Client 直接提交资源余额、单位伤害或胜负结果。
- 不为快速演示而省略唯一 ID、schemaVersion 或幂等 requestId。
- 不随意升级 ForgeGradle/Gradle/Java。
- 不把 GeckoLib 作为核心模型/领域系统的依赖。
- 不自动覆盖旧玩家建筑。

## 7. 任务交接模板

```text
项目：Minecraft Empires
目标版本：Minecraft 1.20.1 / Forge 47.4.x / Java 17
当前任务：<例如 M0-003 SavedData registry>
必须先读：README.md、docs/02-ARCHITECTURE.md、docs/03-TECHNICAL-SPEC-M0-M2.md
范围内：<具体类、接口和行为>
范围外：<明确不做的功能>
验收标准：<逐条可验证条件>
约束：遵循服务器权威、逻辑实体分离、数据 schema 和线程规则。
交付：代码、测试、构建结果、文件清单、文档更新、未验证项。
开始前先检查仓库现状和官方 Forge 1.20.1 API，再简述计划。
```

## 8. 代码审查清单

- [ ] 领域逻辑是否依赖 Minecraft World/Entity？如无必要则移除。
- [ ] 数据保存后是否 setDirty/正确持久化？
- [ ] 同一命令重试是否可能重复扣费？
- [ ] CitizenId 是否可能对应多个 ACTIVE entity？
- [ ] 客户端是否可能伪造结果？
- [ ] 是否可能访问未加载区块？
- [ ] 是否可能在后台线程访问 World/Entity？
- [ ] 是否处理空值、未知 ID 和旧存档？
- [ ] 是否有回归测试和性能预算？
- [ ] 文档、配置 schema 和版本信息是否同步？
